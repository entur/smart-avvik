# Alert rules and observability rollout — runbook

**Date:** 2026-09-11 · **Companion to:** `docs/plans/2026-09-11-001-feat-observability-hardening-plan.md` (R22) and the review `01-review-2026-08-30.md`.

This is the operator half of the observability work: the Grafana alert rules (golden path — rules are created in the UI at [grafana.entur.org](https://grafana.entur.org), so this file is the reviewable definition they are created from), the PagerDuty routing labels, and the rollout checklist for the pieces that cannot run from CI. Every `kix_*` metric named here is declared in `disruptions/api/metrics.py`; if a name here does not grep there, this file is stale — fix whichever is wrong before creating rules.

## Ground rules (from Entur's alerting guide)

- Create rules in a **team folder** (`ki-eksperimentering`) at grafana.entur.org, data source Prometheus/Thanos.
- Every rule carries the routing labels **`service_name: kix-avvik`**, **`env`** (`dev`/`tst`/`prd`), **`severity`** (`critical`/`warning`) — these drive the shared `entur-pagerduty` contact point's Global Event Orchestration.
- Every PromQL below needs the cluster selectors added: `kubernetes_namespace="kix-avvik"` on `kix_*` app metrics, `namespace="kix-avvik"` on `kube_*`/`container_*`, plus `prometheus_group="kub-ent-prd-001"` (prd) / the dev group for dev rules. They are omitted below for readability.
- Alert on symptoms; every rule here has a response (see "response" column notes).

## Rules

| # | Alert | PromQL (add selectors) | Condition / `for` | Severity | Notes |
|---|---|---|---|---|---|
| 1 | Poller stopped | `time() - kix_poller_last_tick_timestamp_seconds > 900` | 5m | critical | The tick heartbeat moves every ~60 s regardless of upstream; 15 min of silence means the poller (or the pod) is gone and `/health` self-healing did not recover it. **No-data → Alerting** (scrape loss and pod death must page, not silence). Do NOT build this on the cycle gauge — cycles are event-driven and pause on quiet nights. |
| 2 | Rebuild stale (observation) | `time() - kix_poller_last_cycle_timestamp_seconds > 3600` | 15m | warning | Cycle freshness, not liveness: legitimate on quiet nights, so this is a daytime-attention rule, not a pager. Consider muting outside 05:00–24:00. |
| 3 | Pod restarts | `increase(kube_pod_container_status_restarts_total[15m]) > 3` | 0m | warning | More than 3 restarts in 15 min — includes the new liveness restarts, so a flapping `/health` shows up here (crash-loop guard: `HEALTH_STALE_AFTER_S=0` disables the staleness branch via a values-only deploy). |
| 4 | Memory near limit | `sum by (pod) (container_memory_working_set_bytes{container!=""}) / sum by (pod) (kube_pod_container_resource_limits{resource="memory"}) > 0.85` | 5m | critical | prd limit is ~2457 Mi; OOM kill on the single replica is a full outage. |
| 5 | Pod not ready | `kube_pod_status_ready{condition="true"} == 0` | 3m | critical | With one replica, not-ready = the service is down. `/health` 503s (dead/stale poller) land here too. |
| 6 | ERROR logged | `increase(kix_log_records_total{level="ERROR"}[10m]) > 0` | 0m | warning | The ERROR channel is deliberately near-silent (verified clean pre-rollout), so any ERROR is worth a look. `labelling_stale`, `thread_died` and `health_degraded` all arrive here. |
| 7 | Push failures | `sum(increase(kix_push_total{result="error"}[30m])) / sum(increase(kix_push_total[30m])) > 0.2 and sum(increase(kix_push_total[30m])) > 5` | 10m | warning | Ratio with a volume guard — single-push blips at low volume must not page. `gone` is not an error (device unsubscribed). |
| 8 | LLM wording failures | `sum(increase(kix_llm_message_total{surface="live",result=~"error\|unavailable\|truncated"}[30m])) / sum(increase(kix_llm_message_total{surface="live"}[30m])) > 0.3 and sum(increase(kix_llm_message_total{surface="live"}[30m])) > 5` | 10m | warning | **`surface="live"` only** — `/meldinger` replay bursts of `ungrounded` are the expected product of prompt work and must not page. Travellers get the deterministic template on failure, so this is quality degradation, not outage. |
| 9 | Labelling stale | `time() - kix_labelling_last_success_timestamp_seconds > 172800` | 30m | critical | 48 h without successful labelling; unlabelled decisions become permanently unknown after 10 days. **No-data → Alerting.** The in-app detector (`event="labelling_stale"`, rule 6) is the primary; this is the belt-and-braces on the metric. |
| 10 | 5xx rate | `sum(rate(kix_http_requests_total{status="5xx",path!="health"}[5m])) / sum(rate(kix_http_requests_total{path!="health"}[5m])) > 0.05` | 5m | critical | **`path!="health"` is load-bearing**: a stale-poller window emits ~24 deliberate `/health` 503s per minute, and without the exclusion this rule double-fires beside rules 1/5. |
| 11 | p99 latency | `histogram_quantile(0.99, sum by (le) (rate(kix_http_request_duration_seconds_bucket{path!="health"}[5m]))) > 5` | 10m | warning | Golden-path default threshold; tune after observing real traffic. |

Suggested rollout order: rules 3–5 first (pure `kube_*`, zero app dependency — they work before the app metrics land), then 1, 6, 9, 10 once the metrics-arrival check below passes, then 2, 7, 8, 11.

## Rollout checklist (operator steps, in order)

1. **Metrics arrival (dev, before creating any `kix_*` rule):** in Grafana Explore against the dev Prometheus, query `kix_poller_last_tick_timestamp_seconds{kubernetes_namespace="kix-avvik"}` — a value must return. If nothing does, check the pod annotations (`kubectl get pod -n kix-avvik -o jsonpath='{.items[0].metadata.annotations}'` should show `prometheus.io/scrape: "true"`, `path: /metrics`, `port: "9464"`), then whether annotation-based discovery is active for this namespace (ask `#talk-utviklerplattform` if not — PodMonitor CRDs would be the alternative). Rules created on absent series silently never fire.
2. **IAM verification (per environment, after `entur apply` lands the manifest change):**
   ```sh
   gcloud projects get-iam-policy ent-kixavvik-<env> \
     --flatten=bindings[].members --filter='bindings.role:roles/cloudtrace.agent OR bindings.role:roles/telemetry.tracesWriter'
   ```
   Expect `application@ent-kixavvik-<env>.iam.gserviceaccount.com` under at least one of the two roles (both were granted; the platform filter drops silently). Until verified, trace-export warnings in the app log are the only signal — tracing fails open and pushes are unaffected.
3. **Trace smoke (dev):** with `TRACING_ENABLED=true` deployed, make one request to `https://kix-avvik.dev.entur.io/impact?...` (any traced route), then open Trace Explorer in **`ent-kixavvik-dev`** (the app project — not `ent-kub-dev`; if empty, check both, the platform docs disagree) and filter `service.name="kix-avvik"`. A poller-cycle trace (root span `poller_cycle` with phase children) should appear within minutes of the next SIRI-SX movement.
4. **tst/prd terraform:** the PR plan validated dev only. On the `terraform.yml` dispatch runs for tst and prd, review the plan step before apply: tst must show the uptime check **without** a notification channel; prd with one.
5. **Grafana rules:** create the table above in the `ki-eksperimentering` folder, dev first, then prd.
6. **PagerDuty:** nothing to configure — the `entur-pagerduty` contact point routes on the `service_name`/`env` labels. Verify one test alert reaches the team.

## What this deliberately does not cover

- SLOs/SLODash (no SLA on this experiment).
- Grafana-as-code: rules stay UI-managed per the golden path; this file is their reviewable source of truth.
- The uptime check's alerting lives in Terraform (`terraform/monitoring.tf`), not Grafana — GCP uptime checks are invisible to Thanos.
